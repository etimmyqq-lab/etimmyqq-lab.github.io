教學看不懂，通常不是你的問題

裝完 Claude Code 之後，第一行該打的不是叫它寫程式，是 `/init`。

十月三十號下午，台中一家做自行車座墊的工廠。廠務經理把筆電轉過來給我看，螢幕上一個黑色視窗，左上角一個游標在閃，其他什麼都沒有。他說昨天晚上照著影片裝，前後弄了四十分鐘，裝好了。然後他盯著那個游標坐了二十幾分鐘，最後把筆電闔上去睡覺。

我問他卡在哪。他說：教學影片到「安裝成功」就結束了，下一段直接跳到「我請它幫我重構這個函式」。中間那一步沒有人講。

這件事我在課堂上遇到大概十幾次了。不是裝不起來，是裝起來之後不知道怎麼開口。

教學看不懂，通常不是你的問題

大部分的 Claude Code 教學是寫給每天都在用終端機的人看的。對他們來說，「cd 到專案目錄然後打 claude」是一句話，不需要解釋。但對一個做了二十年模具、上個月才第一次打開終端機的人來說，這句話裡有三件他不確定的事：cd 是什麼、專案目錄是哪個、打完 claude 之後它為什麼沒反應。

所以我後來教的時候，會把第一次開機拆成很小的動作。

先決定你要讓它看哪一個資料夾。這一步最重要，也最常被跳過。Claude Code 是以「你啟動它的那個資料夾」為它的整個世界。你在桌面啟動它，它眼裡就是你桌面那堆截圖跟 PDF。你在專案資料夾啟動它，它才看得到你真正要處理的東西。

接著開終端機，打 `cd` 加一個空格，然後把專案資料夾從檔案總管直接拖進終端機視窗裡。路徑會自動填好，不用自己打。按 Enter。

然後打 `claude`，按 Enter。第一次會跳出瀏覽器要你登入授權，授權完回到終端機，它就在那裡等你了。

第一行指令：`/init`

到這裡才是重點。很多人第一句就打「幫我把這個報表功能改掉」。先不要。

第一行打 `/init`。

這個指令會讓它把你整個資料夾讀過一遍，然後在根目錄生出一份叫 `CLAUDE.md` 的檔案，裡面寫的是它對這個專案的理解：這是什麼東西、用什麼技術、檔案怎麼擺、怎麼跑起來。之後你每次開啟它，這份檔案都會先被讀進去。

為什麼這一步不能省。因為你不下這個指令，它每次都是從零開始猜。你問第一句，它猜；你問第二句，它再猜一次。猜對的時候很好用，猜錯的時候你要花三句話把它拉回來。

`/init` 跑完之後，建議再做一件事：打開那份 `CLAUDE.md` 看一遍。如果它寫錯了（它會寫錯，特別是你的專案結構比較亂的時候），直接在檔案裡改掉。改一次，之後每一次對話都受益。

另外兩個第一天就該認識的指令：`/help` 會列出全部可用的斜線指令，`/status` 讓你看現在用哪個模型、在哪個目錄、登入狀態是什麼。想離開就打 `/exit`。

就這樣。第一天會的東西不需要比這個多。

為什麼我把這一步叫做起卦前的定位

教易經的時候我會一直強調一件事：起卦之前你得先把問題問清楚。你問「我該不該接這張單」，跟你問「如果我接了這張單，三個月後現金流會卡在哪裡」，就算抽出同一個卦，你讀到的東西完全不一樣。問題模糊，卦象再準你也用不上。

觀卦講的就是這件事。風行地上，先看清局面，再決定要不要動。不是不動，是動之前把你站的位置搞清楚。

`/init` 就是這個動作的技術版本。它不產出任何你要的功能，它只做一件事：讓雙方對「我們現在在談的是什麼」有共識。你省掉這一步，後面每一句對話都在補這個坑。

我自己陪客戶做企業 AI 導入的時候，這一步還會額外加一句。`/init` 跑完，我會打：「請你用三句話告訴我，這個專案是做什麼的，資料從哪裡進來、到哪裡出去。」

它答對了，可以開始。答錯了，現在修比等它改錯三個檔案再修便宜太多。

幾個真的會踩的坑

第一個，在家目錄或桌面啟動。前面講過了，這是最常見的一個。

第二個，`/init` 跑完不看產出的那份檔案。它是之後所有對話的地基，地基歪了你不會馬上發現，但三天後你會開始覺得「它怎麼老是搞錯」。

第三個，把它當搜尋框用。一行一個問題，答完就關掉。這樣用不是不行，只是你裝這個東西的意義不大。它的價值在於它記得這個專案，而記憶是累積出來的。

那天在台中，我讓那位經理自己打完 `/init`，看它跑了一分多鐘，吐出一份把他們排程腳本的功能寫得八成正確的檔案。他看了很久，說了一句：「原來它看得到。」

對，它看得到。但你得先讓它看。

常見問題

我完全不會寫程式，裝 Claude Code 有意義嗎？
有，但你要換個期待。我有幾個學員是行政和會計背景，他們拿它做的事是整理一整個資料夾的報表、批次改檔名、把四十個 Excel 的某一欄抽出來。這些不是寫程式，是處理檔案。`/init` 對他們一樣有用，差別只在那份 `CLAUDE.md` 寫的不是技術架構，是「這個資料夾裝的是什麼資料」。
`/init` 會不會偷偷改到我原本的檔案？
它只新增一份 `CLAUDE.md`，不會動你其他東西。不過習慣還是要養：第一次在重要的資料夾裡用它之前，先把整個資料夾複製一份備份。不是因為它會亂改，是因為你接下來會開始叫它改東西，那時候有備份你才敢放手。
每次開 Claude Code 都要重新打一次 `/init` 嗎？
不用。`CLAUDE.md` 存在資料夾裡，它開啟時自己會讀。只有在專案結構大改之後才值得重跑一次。更常見的做法是手動編輯那份檔案，想到什麼規則就加一行，它比重跑一次準。
