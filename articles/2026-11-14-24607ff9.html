第一層：你跟工具廠商之間

十月二十九號下午，台中大里一家做碳纖維輪組貿易的公司，老闆把筆電轉過來給我看。螢幕上是他用 Claude Code 花三個晚上做出來的報價單產生器，讀 Excel 的料號跟匯率，三秒吐一份 PDF。他問的不是程式怎麼改，他問：這東西我可以拿去賣給同業嗎？會不會哪天被告？

我當場沒有直接回答。因為「可以商用嗎」這五個字裡面其實塞了三個不一樣的問題，而大部分人只想到第一個。

第一層：你跟工具廠商之間

這層最單純。Anthropic 的使用條款，不管是個人訂閱方案還是商業方案，都寫了輸出內容的權利歸使用者。所以單就「我用了這個工具，產出的東西是不是我的」這題，答案是你的。可以賣、可以放進產品、可以不告訴客戶是 AI 寫的。

但條款會改。我陪那位老闆做的第一件事，是打開當時最新版的條款頁面，把關於 Outputs 的那一段截圖存進專案資料夾，連日期一起。不是不信任廠商，是三年後如果真的有爭議，你要能證明你當時依據的是哪一版。

就這樣，第一層十分鐘解決。

第二層：著作權法保護不保護

這一層比較多人沒想到。台灣智慧財產局在 2023 年就表過態：AI 自動生成的內容，如果人沒有實質的創作參與，不算著作權法保護的著作。美國著作權局的立場差不多。

翻成白話：你拿 Claude Code 生出來的程式碼去賣，沒有人能阻止你；但如果有人把你的程式碼整段抄走，你也很難拿著作權去告他。因為那段「作品」法律上可能根本不認你是作者。

老闆聽到這裡臉有點垮。我說，先別急，這件事反過來想是好事。

你的護城河從來不在程式碼本身。那位老闆真正值錢的東西是什麼？是他知道碳纖維輪組報價要考慮哪七個變數、知道哪些客戶習慣 FOB 哪些要 CIF、知道匯率浮動超過多少要重新報。這些他寫進 prompt 裡的業務邏輯，才是別人抄不走的。程式碼只是把他腦子裡的規則印出來。

所以我給他的建議很土：把你自己改過的地方留下紀錄。哪一段是你手動調整的計算邏輯、哪個判斷式是你加的、為什麼加。git commit 訊息寫清楚。人的參與痕跡越具體，日後主張權利的空間就越大。而且老實說，寫這些紀錄的過程本身就會逼你把業務邏輯想得更清楚。

第三層：你的程式碼裡有別人的東西

這層最容易出事，也最少人檢查。

Claude Code 寫程式的時候會引用開源套件。有的套件授權很寬鬆，像 MIT、Apache 2.0，拿去商用沒問題；有的是 GPL 或 AGPL，意思是你如果把它包進產品賣出去，你的產品原始碼也得公開。對一個想把報價單系統賣給同業的老闆來說，這就是地雷。

我們那天花了快四十分鐘做這件事。方法不難，直接在 Claude Code 裡下：

`列出這個專案所有直接與間接依賴的套件，逐一標出授權類型，GPL、AGPL、LGPL 的另外列一張表，並說明若商用販售會有什麼義務。`

跑出來 23 個套件，其中 1 個是 LGPL 授權的 PDF 產生套件。還不到不能用的程度，但有附帶義務。我們最後換成另一個 MIT 授權的替代品，Claude Code 改了 11 行就過了。

另外還有一個比較隱晦的：你貼進去的東西。那位老闆為了讓 Claude Code 懂他的報價邏輯，把過去兩年的真實客戶報價單丟進去當範例。這些檔案裡有客戶的公司名、聯絡人、成交價。這不是著作權問題，是保密問題。如果他跟客戶的合約裡有保密條款，這個動作本身就可能違約，跟程式碼能不能賣沒關係，但一樣會被告。

後來我們把範例檔全部換成去識別化的版本。多花一個小時，心安。

訟卦講的其實不是打官司

我一直覺得「可以商用嗎」這題，老闆們問的時間點都太晚。程式寫完了、想賣了、才回頭問能不能。

易經六十四卦裡有一卦叫訟，就是爭訟的訟。很多人以為這一卦講的是怎麼打贏官司，其實它的大象辭講的是另一件事：「君子以作事謀始」。意思很直接，有智慧的人在開始做事的時候就把可能起爭執的地方想清楚，而不是出事以後才找律師。

那天跟老闆說完這句，他沉默了一下，然後說：所以我應該在開始寫之前就先做那個授權檢查。我說對，而且應該在開始之前就決定範例檔要不要去識別化。

這跟 AI 無關，跟易經也無關。只是我們習慣先做再想。Claude Code 把寫程式的門檻降到三個晚上可以搞出一個產品，但「開始之前先想一下」這件事的門檻，從來沒有人幫我們降。

他後來有把那套報價單系統賣出去，第一個買家是他同業公會裡認識十幾年的朋友，賣了一個我不方便講的數字。合約上寫了「本軟體部分程式碼由 AI 輔助產生」。對方看了一眼，說喔，然後簽了。

就這樣。

常見問題

我用的是個人版 Claude 月費方案跑 Claude Code，寫出來的程式也能拿去公司用或賣嗎？
條款層面可以，輸出歸你。但我會多做一件事：如果這套程式要賣，或是公司要長期用，把帳號改成公司名義的商業方案。不是法律上一定要，是日後若有爭議，用個人帳號寫出來的東西要主張是公司資產，多一層麻煩。順便把當時的條款頁面截圖存檔，標日期。
怎麼知道 Claude Code 幫我裝的套件有沒有 GPL？我看不懂授權條款。
不用自己看懂。直接在 Claude Code 裡要它列清單：請它把所有依賴套件的授權類型列成表，特別標出 GPL、AGPL、LGPL，並且用白話解釋每一種對商用販售的影響。Python 專案也可以跑 `pip-licenses`，Node 專案跑 `npx license-checker`，兩個都是一行指令就有結果。看到 GPL 類的，問它有沒有 MIT 或 Apache 授權的替代品，多半有。
如果客戶問「這程式是不是 AI 寫的」，我要承認嗎？
我的做法是主動寫進合約或說明文件，一句「部分程式碼由 AI 輔助產生，經人工審查修改」就好。理由不是法律義務，是信任。我陪過的客戶裡沒有一個因為這句話掉單，倒是有一個因為被對方自己發現、覺得被隱瞞而鬧僵。先講，比被發現好。
