他第一次寫的 prompt

同一個需求，他用中文寫了 47 個字丟給 Codex，三輪跑下來有兩輪把「未稅金額」抓成「含稅金額」；換成英文重寫，三輪只錯一輪。他當場說「看來還是要用英文」。但我請他把中文那版重寫成五條、98 個字，再跑三輪，全對。所以那天測出來的不是語言差異，是把需求拆開寫的差異。

十一月二十四號下午三點多，彰化鹿港一家做五金零件代工的工廠，二十八個人，鐵皮屋隔出來的辦公室裡冷氣聲音比說話聲大。老闆的兒子三十一歲，接班第二年，負責把家裡的紙本流程搬進電腦。他學 Codex 兩個禮拜，卡在一支腳本上：把 ERP 匯出的出貨明細整理成客戶月結對帳表。他說他懷疑是中文的問題，因為他看到的討論裡大家都說英文 prompt 比較準。

這個問題我被問過不只一次，而且問的人通常已經自己默默切成英文寫了。有些人英文其實不錯，寫起來只是慢；有些人根本不會寫，用翻譯軟體翻完再貼進去，整個流程多兩分鐘。所以那天我沒有直接回答，我們做了個小實驗。

他第一次寫的 prompt

「幫我把 ERP 匯出的出貨明細整理成客戶月結對帳表，金額要加總，客戶要分開。」

四十七個字。讀起來好像沒什麼問題，老實說我第一眼也覺得沒問題。

但那張 CSV 打開來有二十三個欄位，裡面有四個長得很像的金額欄：`amount`、`amount_untaxed`、`amount_taxed`、`amount_after_discount`。「金額要加總」是要加哪一個？

「客戶要分開」也有兩種讀法：一個客戶一張工作表，還是同一張表裡按客戶排序、每段尾巴加一列小計。

還有月結這件事。他們出貨日跟發票日經常差三到五天，月底那幾天特別明顯。十月三十一號出的貨，發票開在十一月二號，這筆算十月還是十一月？他心裡很清楚答案是看發票日，因為對帳要跟客戶的帳期對上。但這句話沒寫進去。

三個洞，全在他腦子裡，一個字都沒在 prompt 裡。

英文那版為什麼比較準

他改寫英文的時候，做了一件他自己沒注意到的事。

他英文不到可以直接下筆的程度，所以他先把需求拆成五條中文短句，再一條一條翻。翻譯這個動作有個副作用：一句含糊的中文根本翻不出來。「金額要加總」要翻成英文，你就得先決定是哪個金額，因為你得挑一個欄位名貼上去。

所以他那份英文 prompt 不是「英文版」，是「被迫寫清楚版」。

我請他把那五條拆解直接用中文寫，專有名詞保留原文不要翻。九十八個字。三輪全對。

那天之後我又拿同樣的方法在另外兩個客戶那邊試過，一家是台中做機械加工的、一家是高雄做貿易的，狀況都差不多：寫清楚的中文跟寫清楚的英文，結果看不出差別；寫糊的中文跟寫糊的英文，一樣都會錯，只是錯的地方不同。

我不是說語言完全沒影響。專有名詞、函式名、套件文件這些東西原文就是英文，你用中文描述它們會多一層轉譯，轉譯就有誤差。不過這個誤差跟「需求沒寫清楚」造成的誤差比起來，小很多。

用中文寫 Codex prompt 的五格

這是我後來整理給客戶用的，做 Codex 教學我都從這張表開始講：

  1. 現況。檔案放哪、幾個欄位、現在跑出來長什麼樣。有錯誤訊息就整段貼原文，不要自己摘要。
  2. 範圍。要動哪個檔案、哪個函式，以及哪些地方不准動。第二句比第一句重要。
  3. 輸入輸出。給它什麼、要它吐什麼，格式寫死。欄位順序、檔名規則、小數位數都算。
  4. 判斷規則。所有「看情況」的地方都要給一條規則。你想得到的每一個「如果」，都寫下來。
  5. 驗收。我怎麼知道它做對了。最好給一筆你手算過的資料，直接說正確答案是多少。

專有名詞一律貼原文。他有一輪失敗就是因為把 `invoice_date` 寫成「發票日期欄位」，而那張 CSV 裡同時有 `invoice_date` 和 `inv_dt` 兩個欄位，一個是開票日、一個是鍵入日。

這件事跟易經有關係

我帶客戶抽卦牌的時候，整個流程最花時間的不是抽，是前面立問那十幾分鐘。

最常聽到的問題是「我公司明年會怎樣」。這種問題抽到任何一卦都能講得通，因為它沒有可以被回答的邊界。我會請對方改寫，改到類似「要不要在明年三月前把第二條產線的投資案送董事會」這種程度。問題一具體，卦象才有話可說，答案才有辦法接到行動上。

易經裡的立問跟寫 prompt 是同一件事。你問的方式決定了你拿到什麼樣的答案，不是因為那邊有個神祕機制在挑嘴，是因為一個模糊的問題本身就不包含足夠的資訊去生出一個明確的答案。

中小企業數位轉型做到工具這一層，很多人以為卡在工具不夠好。我看到的比較多是卡在交代事情的能力。你交代給 Codex 交代不清楚，交代給上禮拜剛到的新人大概也是一樣的句子。

那天離開前，他把那五格印出來貼在螢幕旁邊。A4 大小，字放得很大。他說貼在那不是為了提醒自己怎麼跟 Codex 講話。

是提醒自己交代事情給人的時候也該這樣。

常見問題

那我到底要用中文還是英文寫 prompt？
寫得清楚的那個語言。如果你英文要查字典才寫得出來，就用中文，省下來的時間拿去把需求拆細。唯一要堅持的是：欄位名、函式名、檔案路徑、錯誤訊息、套件名稱一律貼原文，不要翻成中文。中英混著寫完全沒問題，沒人會扣你分。
我已經寫很詳細了但還是會改錯地方，問題在哪？
多數情況是漏了「不准動什麼」。大家習慣寫自己想要什麼，很少寫不要碰什麼。加一句「只改 `export_report.py` 這個檔案，其他檔案不要動」，再加一句「原本的 `main()` 保留不變」，被改壞的機會會少很多。
一個 prompt 要寫到多長才夠？
長度不是指標，有沒有留下「看情況」的空白才是。寫完自己讀一遍，每看到一個可以有兩種解釋的地方就補一條規則。我那位客戶最後跑對的那版是九十八個字，不算長，只是沒有洞。
