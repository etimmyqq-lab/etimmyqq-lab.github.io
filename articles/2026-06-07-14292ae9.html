開會前整理數據要花幾個小時，Codex 省掉的到底是哪段時間？

台北有個做醫療器材進口的客戶，去年八月找我做了一次諮詢。

他的問題不是「要不要用 AI」，是「我每次開會前要花五、六個小時整理數據，我到底在花時間在哪裡？」

他說他們公司每個月有一次管理會議。會前要準備三份報告：上月銷售、庫存現況、應收帳款。這三份東西分別存在 ERP 系統、倉儲系統、和財務部自己維護的一個 Excel 總表。每次要整理，就得登入三個地方、把資料導出來、再手動對欄位、再做成一份可以看的表。

「五個小時是快的。有時候資料有問題要去問人，那就更久。」

他問我：「Codex 能幫我省掉這個嗎？」

我沒有直接回答他。我問他：「你花這五個小時，最難熬的是哪一段？」

他想了一下說：「不是整理本身，是對完才發現數字對不起來，然後要找原因。」

這個答案改變了我給他建議的方向。

時間花在哪裡，Codex 才有機會幫你

很多人聽到「Codex 可以幫你整理數據」，第一反應是：那我以後開會就不用準備了？

不是這樣的。

Codex 的能力在於——你告訴它你要什麼，它去寫程式碼幫你把資料抓出來、算出來、整理成你要的格式。如果你每次都在做「從這個地方匯出，放到這個地方，按這個格式排」這種固定流程，Codex 寫一次腳本，之後你就只是按一下執行。

那位醫療器材的客戶，後來我陪他做了一件事：先把他整理報告的步驟用中文寫出來，一步一步，寫得非常詳細。光這個步驟就花了我們一個小時。

然後他才用 Codex 把這份「步驟說明」轉成實際能執行的 Python 腳本。

第一次生成出來的腳本有問題，跑到一半報錯。他把錯誤訊息貼回去給 Codex，Codex 修好了。前後加起來大概花了三個多小時。

但那個腳本做好之後，下個月他整理同樣三份報告，花了多少時間？

二十分鐘。

不是因為 Codex 多厲害。是因為他真的把流程想清楚了，然後 Codex 把那個清楚的流程自動化了。

Codex 教學裡最常被跳過的一步

我在做 Codex 教學的時候，發現一個很普遍的狀況：大家都急著去問 Codex「幫我分析這份數據」，但根本沒有先想清楚自己要的是什麼。

Codex 接受模糊的問題，但它會給你模糊的答案。

這讓我想到一件事。我有個客戶，同時在學習用卦牌做決策輔助。他有一次開玩笑說：「老師，你教 Codex 的方法跟教我問卦的方法一樣啊。你都在逼我先把問題講清楚。」

他講的沒錯。

問卦的第一步，不是拿起卦牌，是把你真正想問的那件事，用一句話說清楚。「我要不要做這個決定」這樣的問法太寬，卦的回應你也看不懂。「我如果在這個月執行這個決定，主要的風險是什麼」這樣問，卦才給得出有用的訊息。

Codex 也是這樣。

「幫我分析上個月的業績」，Codex 不知道你想看什麼角度。「把上個月每個業務員的成交金額、成交件數、平均件單價，用表格列出來，並標出哪三個人低於平均」，Codex 才知道要做什麼。

問題問清楚，工具才有辦法發揮。這不是什麼新道理，只是現在更明顯了。

真正省掉的時間，不是「整理」，是「等」

回到那位醫療器材客戶的例子。

他說開會前最難熬的不是整理，是發現數字對不起來要找原因。

這個問題，Codex 幫得到嗎？某種程度上可以。

如果腳本寫好了，每次跑出來的數據格式一致，那「數字對不起來」這件事發生的機率就小很多，因為來源、欄位定義、計算邏輯都是固定的。變數少了，異常就容易發現。

但真正的問題如果是「ERP 裡的庫存數跟倉儲系統的庫存數有落差」，這種結構性問題，Codex 幫你發現，但解決不了。解決要靠你去問倉管、問採購，那個時間還是得花。

Codex 省掉的是你在三個系統之間切換、複製貼上、手動核對欄位名稱的時間。那段時間其實很傷人，因為它需要你集中注意力，但又沒有任何智識含量，你的腦子一直在消耗卻沒有任何收穫。

省掉那段時間，你才有精力去思考「為什麼這個月應收帳款比上個月多了十八%」這種真正重要的問題。

怎麼開始

如果你現在開會前也在做類似的事，我給你一個具體的起點：

下次整理報告之前，先把你的步驟寫下來。不用寫得多精準，就用你自己的語言，把「我要先去哪裡、做什麼、得到什麼、再去哪裡」這個流程記下來。

然後把這份流程說明貼給 Codex，問它：「這個流程我可以自動化嗎？如果可以，第一步要做什麼？」

Codex 會告訴你哪些步驟可以用程式碼做，哪些還是需要你手動。通常你會發現，八成的重複動作是可以自動化的。

第一次嘗試不會完美，可能要來回幾次。但第一次做完之後，你就知道這條路走不走得通了。

那位台北客戶，現在開會前的準備工作，他讓助理按一下跑腳本，二十分鐘後去取報告。他自己用那段時間喝咖啡、看昨天沒看完的產業新聞。

他說：「老師，我以前以為整理報告是我工作的一部分。現在發現那根本不是工作，那是在做工具該做的事。」

這句話我覺得說得很準。

常見問題

Codex 需要會寫程式才能用嗎？
不需要。你需要的是能把需求說清楚——就是「我要從哪裡拿什麼資料、整理成什麼格式」。這件事用中文說就可以，Codex 負責把它轉成程式碼。當然，如果你完全不懂程式，遇到腳本出錯時除錯會比較吃力，可能需要多幾輪對話才能修好。但基本的整理任務，不用懂程式。
我的數據在 Excel 裡，Codex 也能處理嗎？
可以。Codex 可以寫 Python 腳本讀取 Excel 檔，做計算、篩選、合並、格式整理，然後輸出成新的 Excel 或其他格式。前提是你要告訴它你的 Excel 長什麼樣、欄位叫什麼名字、你要做什麼操作。第一次可能要把欄位結構描述給它看，之後就順了。
Codex 跟用 ChatGPT 上傳 Excel 分析有什麼不同？
最大的不同是可重複使用。ChatGPT 上傳 Excel 是一次性的——你得到一個回答，下次換新數據又要重新上傳、重新描述需求。Codex 幫你寫的腳本可以存起來，下個月跑一樣的流程只要執行腳本就好。如果你每個月都要做同樣的整理，Codex 的腳本方案比 ChatGPT 的一次性分析划算得多。
