你要學的那一段，誰都教不了

十一月四號晚上七點多，彰化一家做水五金出口的老闆在辦公室問我這題。他六十一歲，桌上壓著兩張名片：一張是他外甥的，二十六歲，在台北一家電商做後端；另一張是我同業，五十三歲，做企業顧問快二十年。他手指在兩張名片中間來回點了幾下，說，你跟我講實話，我該找誰教。

我的回答讓他有點不高興。我說這兩張都先放回抽屜。

因為他上個月已經學過一次了。外甥中秋回彰化，順手教了他兩個小時 Claude Code。老闆說那兩個小時他聽得懂，外甥在螢幕上示範，他跟著打了幾個指令，當場跑出東西來，他還拍了照發到家族群組。隔天早上九點十分，他自己坐在辦公室打開終端機，第一個指令就停住。

不是指令打錯。是他不知道該叫它做什麼。

這個停住的位置，我在不同老闆身上看過至少七八次。年齡從四十幾到六十幾，產業從模具到食品代工都有。卡住的點從來不是語法，不是安裝，不是哪個選項要打開。是老闆講不出自己公司那件事的規則。

你要學的那一段，誰都教不了

水五金這家公司有一件事老闆想交出去：客戶寄來的詢價單整理成報價單。一週大概十二到十五份，一份要花他們業務助理二十分鐘上下。

我問老闆，這二十分鐘裡面助理在做什麼判斷。他講了大概三分鐘，講得很流暢，前面都是對的。然後我問，如果客戶沒填交期呢。他停了兩秒，說，那她會問我。我說那你怎麼回答。他又停了，說，看是哪個客戶，老客戶就照他上次的天數抓，新客戶我會去看庫存。

這段話是重點。前面三分鐘的流程，外甥聽得懂，顧問也聽得懂。後面那兩段停頓，才是真正要寫進去的東西。而這兩段停頓只存在他腦袋裡，跑了二十幾年，從來沒有變成文字。

年輕工程師教不了這一段，因為他不知道你的客戶有新舊之分。同齡顧問也教不了，因為他沒做過水五金出口。

所以「找誰教」這個問題問錯了。不是年齡的問題，不是職業的問題。真正的問題是：你有沒有先把自己那件事講清楚，再去找人。

面試老師的方法：看他第一個問題問什麼

那天我讓老闆回去做一件事，不是找人，是先寫一份東西。

打開記事本，寫你想交出去的那件工作，自己平常怎麼做。不用漂亮，不用完整，寫十行以上就好。輸入是什麼檔案、你會看哪幾個欄位、判斷的規則是什麼、什麼情況會變成例外、例外怎麼處理、輸出要長什麼樣。

他隔了四天傳給我，三十二行。傳完附了一句話：原來我自己也沒想清楚。

這三十二行有兩個用途。

第一個用途是面試老師。把這份東西給你要找的人看，然後看他第一個問題是什麼。

如果他先問你電腦裝了什麼、你用 Windows 還是 Mac，這個人會教你工具。你會學到怎麼安裝、怎麼打指令、怎麼看畫面上的提示。這些不是沒用，但這些是 YouTube 上就有的東西。

如果他先問交期沒填的這個例外一個月出現幾次，這個人會教你怎麼用。因為他已經在想，這個例外要不要寫進規則、寫進去會不會讓整件事變複雜、還是乾脆讓它停下來問人。

這兩種問題的差別，比年齡差三十歲重要得多。我見過二十八歲的工程師第一句就問例外頻率，也見過五十幾歲的顧問花半小時在教怎麼開終端機。

第二個用途，那三十二行本身就是教材。

把你寫的那份東西存成 CLAUDE.md

這段講具體一點。

Claude Code 在一個資料夾裡工作的時候，會自動讀取那個資料夾裡一個叫 `CLAUDE.md` 的檔案，把內容當成背景知識。所以你寫的那三十二行流程，不要放在記事本裡，直接存成專案資料夾裡的 `CLAUDE.md`。

常見問題

所以那位老闆最後到底找了誰教？
誰都沒找。我們花了兩個下午，把報價單那十二種狀況一條一條寫出來，包括「老客戶照他上次的天數抓」這種他自己都沒意識到的規則。寫完那份文件，他外甥電話裡二十分鐘就把剩下的教完了。
我連自己公司的規則都講不清楚，是不是代表我管理有問題？
不是。能講清楚的規則早就寫成 SOP 丟給員工了，留在你腦子裡的本來就是那些「要看情況」的判斷。我給的作法很土：叫助理連續十天，每次來問你的時候，把你回答的原話抄下來。十天就夠了。
那年輕工程師跟同齡顧問，真的完全沒差別？
有差，差在規則寫完之後。工程師教你怎麼把文字變成能跑的指令比較俐落，同齡顧問聽得懂你說「這個客戶不能等」背後指的是什麼。不過順序不能倒過來，規則還沒出來就上課，誰教你都會在隔天早上九點那個位置停住。
