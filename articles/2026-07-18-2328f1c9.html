交給員工，你交出去的其實是判斷權

老闆該自己學 Claude Code 還是交給員工，我的答案是老闆自己得學，但學的東西跟員工不一樣。員工學怎麼操作，老闆學怎麼判斷。老闆學到能看懂員工交出來的成果對不對、能開口問對一句話的程度就夠了，不必變成打指令最快的那個人。

上週三下午，一個做冷凍水餃代工的老闆坐在我對面，手機開著擴音，另一頭是他請的工讀生。他問我：「老師，我這個歲數了，還要自己學這個嗎？我直接叫小朋友弄不就好了。」我反問他一句：「那小朋友弄出來的東西，你看得懂哪裡對哪裡錯嗎？」他愣了一下。

這就是重點。

交給員工，你交出去的其實是判斷權

很多老闆以為「交給員工」是交出操作，其實你交出去的是判斷。

Claude Code 這種工具最麻煩的地方，不是它會出錯，是它出錯的時候看起來很像對的。它會很有自信地把一段程式改好、把一批檔案整理完、把報表拉出來。你員工不見得看得出那裡面有沒有問題，你如果也看不出來，那這整條線上就沒有人在守門。

我那個做水餃的老闆，後來吃過一次虧。工讀生用 Claude Code 幫他把三年的訂單資料整理成一張總表，數字漂亮、格式乾淨，老闆看了很滿意就拿去跟銀行談貸款。結果銀行的人翻兩頁就發現，去年第四季有一整個月的退貨沒有被算進去，毛利被灌高了。不是工讀生偷懶，是他根本不知道退貨要另外扣，Claude Code 也不會主動問他。

那一刻老闆才懂，他省下來的不是學習時間，是一個他本來該自己守的關。

老闆要學到什麼程度就好

我通常這樣跟老闆講：你不用學到會自己寫指令，但你要學到三件事。

第一，你要知道這工具大概能做什麼、不能做什麼。不然員工說「這個 AI 做不到」，你連他是真做不到還是不想做都分不出來。

第二，你要看得懂結果。不是看格式漂不漂亮，是看數字合不合理、邏輯通不通。這個能力其實你本來就有，你做生意這麼多年，一張報表對不對你心裡有數，你只是要把這個直覺套到 AI 生出來的東西上。

第三，你要會問。這是最關鍵的。AI 給你的答案好不好，八成取決於你問得清不清楚。老闆最該學的，是怎麼把一個模糊的生意問題，拆成一個 AI 聽得懂、答得出來的具體問題。

這三件事，花一個週末摸，大概就有個底了。真的不用很久。

易經裡有一句話，剛好講的是這件事

《易經》講「君子不器」。器就是工具、是專才。這句話的意思不是叫你什麼都不會，是說一個帶人的人，價值不在於你變成某個工具的高手，而在於你能不能站在工具之上看事情。

我這幾年幫企業導 AI，最怕遇到兩種老闆。一種是完全不碰，全丟給員工，結果員工做什麼他都只能點頭；另一種是自己栽進去，天天研究指令，反而把該做的決策丟在一邊。這兩種都偏了。

易經六十四卦裡有個蒙卦，講的是啟蒙、學習。蒙卦的卦辭很有意思，它說不是老師去求學生，是「童蒙求我」，學的人要主動。但它同時又講「山下出泉」，水剛從山裡冒出來，方向還沒定，要慢慢引。老闆學 AI 就是這個狀態。你不用一次學透，你要做的是先冒出那股泉水，先動起來，方向邊走邊修。

我那個做水餃的老闆，後來每週抽兩個晚上，跟工讀生一起坐在電腦前。他不打指令，他只做一件事：工讀生每做一步，他就問「你為什麼這樣做」「這個數字哪來的」。三個月後，換工讀生開始怕他了，因為老闆問的問題越來越刁，工讀生亂弄馬上被抓包。

那家公司的 AI 導入，就是從老闆學會問問題那天開始，才真的走上軌道。

所以到底自己學還是交給員工

兩個都要。員工負責手，老闆負責眼睛跟嘴。手可以外包，眼睛跟嘴不行。

你如果只想選一個，那選學到「能判斷」。因為一家公司裡，可以沒有最會操作的老闆，不能有一個看不懂員工在做什麼的老闆。

常見問題

我快五十歲了，學這個是不是太慢？
不會。你要學的不是寫程式，是判斷，而判斷這件事你反而比年輕人強，因為你有生意經驗。我教過六十幾歲的老闆，他打字很慢，但他一眼就看出報表哪裡怪，那個是年輕工讀生學十年也學不來的。工具的操作可以交出去，商業判斷交不出去。
我請一個懂的員工不就好了，幹嘛自己學？
可以，但你要想清楚，那個員工哪天離職，你這條線就斷了。而且他做的東西如果你完全看不懂，你等於把公司一部分決策權交給一個你無法驗收的人。自己學到能看懂的程度，不是要搶他的工作，是要留一個守門的人，那個人最好是你。
老闆自己學，一週要花多少時間才夠？
如果目標是「能判斷、能問對問題」，不是「能自己操作」，一開始一週兩三個晚上、每次一小時，兩三週就有感覺了。之後維持一週看員工做一兩次、問問題就好。重點不是時數，是你有沒有真的坐下來看員工怎麼做、開口問為什麼。
