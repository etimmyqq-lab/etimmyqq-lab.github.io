先講清楚程式該做什麼、不該做什麼

十一月四號上午十點，台南永康一家做沖壓模具的公司，會計把兩疊紙放在會議桌上。左邊是銀行當月進帳明細，142 筆。右邊是系統列印的應收帳款明細，138 張。他說這件事每個月要做九個小時，其中大概六個小時，是在確認那些本來就沒問題的款項真的沒問題。

真正對不起來的，11 筆。

所以當他問我「會計用 Claude Code 可以自動對帳嗎」，我的回答是：可以，但你要的其實不是自動對帳。你要的是有人幫你把那 131 筆正常的挑掉，讓你只看剩下的 11 筆。這兩件事聽起來很像，做起來差很多。

先講清楚程式該做什麼、不該做什麼

我在企業 AI 導入的案子裡最常看到的失敗，是老闆要求「全自動」。全自動的意思是程式自己判斷、自己寫回系統、自己結案。會計聽到這句話會立刻反對，而且他是對的。

帳務這種東西，錯一筆的成本不是修一下就好，是下個月整串都歪掉。所以我給的界線很硬：程式只做比對跟標記，不改任何一個數字，不碰 ERP，輸出就是三個 CSV 檔。

`matched.csv`（配對成功） `unmatched_bank.csv`（銀行有錢進來、帳上找不到對應） `unmatched_ar.csv`（帳上有應收、銀行沒收到）

人只看後面兩個。第一個是給事後抽查用的。

這樣做的好處是，就算程式寫錯，最壞狀況是配對變少、要人看的變多，不會出現錯誤配對被當成正確入帳。失敗的方向是安全的。

實際怎麼做，會計自己就能跟著走

步驟一，把資料變成兩個 CSV。

銀行那邊，網銀都能下載當月交易明細。欄位通常是日期、摘要、存入金額、餘額。帳務系統那邊，匯出未銷帳應收明細，欄位是客戶名稱、發票號碼、金額、到期日。兩個檔案丟進同一個資料夾，取名 `bank.csv` 跟 `ar.csv`。

步驟二，在那個資料夾開終端機，輸入 `claude`，然後把需求講清楚。我當天讓會計自己打的那段大概長這樣：

`讀這個資料夾的 bank.csv 和 ar.csv，寫一支 reconcile.py 幫我對帳。配對規則：金額必須完全相等；銀行日期在發票到期日前後 7 天內；銀行摘要裡的戶名跟客戶名稱做模糊比對，相似度 0.85 以上。一筆只能配一次。輸出 matched.csv、unmatched_bank.csv、unmatched_ar.csv 三個檔，不要改原始檔案。`

重點在中間那三行規則。那不是程式的事，是你的事。會計腦袋裡本來就有這套規則，只是從來沒寫下來過。

步驟三，跑完先驗一次。拿上個月已經人工對完的資料餵進去，看程式配對的結果跟人工差幾筆。那天我們試了十月份，程式配了 127 筆，跟人工比對差 4 筆，原因都一樣：客戶匯款用的是老闆個人戶頭，戶名完全對不上。

步驟四，把例外寫進規則。我們加了一個 `alias.csv`，兩欄，匯款戶名跟對應客戶，叫 Claude Code 在比對前先查這張表。加完再跑，差異剩 1 筆。那 1 筆是真的有問題，客戶少匯了 3,200 元的匯費。

整個過程從開始到能用，兩個半小時。會計本人全程坐在電腦前打字，我只負責在旁邊說「這句話要講得更具體」。

大家最容易踩的那個坑

模糊比對的門檻值。

相似度設 0.6，程式會把「大誠企業」配到「大成實業」去。設 0.95，同一家公司多打一個空格就配不上。我的建議是從 0.85 起跳，跑完看配不上的清單再往上下調。這個數字沒有標準答案，每家公司的客戶名稱長相不一樣。

還有一個更隱性的問題：一筆匯款付三張發票。很多中小企業的客戶會這樣做。純金額相等的規則抓不到，要另外加組合配對的邏輯，讓程式去試 2 到 3 張發票的加總。這會讓執行時間變長，但對製造業來說幾乎是必要的。先跑基本版，第二版再加。

訟卦講的那句話

對帳這件事，我後來發現跟易經卦牌裡的訟卦講的是同一回事。

訟卦的象辭有一句：君子以作事謀始。做事情要在一開始就把規矩定好，不然後面就是爭執。

我陪過的對帳案子裡，真正對不起來的差異，大概七成不是算錯，是當初收款條件沒講清楚。匯費誰付？對帳單什麼時候寄？客戶合併付款要不要附明細？這些事沒在簽約的時候寫死，三個月後就變成會計坐在那邊猜。

程式解決不了這個。你把對帳自動化了，它只會更快、更清楚地把當初沒講清楚這件事攤在你面前。

十一月四號那天最後，老闆看著 unmatched 清單上剩下的那幾筆，沉默了一下，說了一句：原來問題在我的報價單。

這才是自動化真正的價值。不是省九個小時，是讓你看見那九個小時裡被淹掉的 11 筆。

卦也是這樣用的。它不幫你決定，它逼你把問題問到夠清楚，清楚到答案自己浮出來。

那疊紙現在還在他們會議室，沒人再印了。

常見問題

我完全不會寫程式，Claude Code 真的裝得起來嗎？
裝的部分最麻煩，但只有一次。先裝 Node.js，再一行 `npm install -g @anthropic-ai/claude-code`，然後在你的資料夾裡打 `claude` 就進去了。真正的門檻不在安裝，在你能不能把對帳規則用中文講清楚。我見過會計講得比工程師還精準，因為那套規則本來就在他腦子裡跑了十年。
帳務資料拿給 AI 處理，會不會外洩？
要分兩段看。Claude Code 寫出來的 `reconcile.py` 是在你自己電腦上跑的，執行過程完全離線，金額不會出去。但你跟它對話的內容會上雲端。我的做法是：規劃階段只給欄位名稱跟假資料，等腳本寫好，真實的客戶名稱跟金額自己跑。這樣多花十分鐘，但睡得著。
那會計會不會被取代？
九小時變一小時，剩下八小時拿去做什麼，這才是真正的問題。那家公司的會計現在每週花兩小時看客戶的付款週期變化，上個月提前抓到一家客戶從 45 天拖到 72 天。這件事以前沒人做，不是不會做，是沒時間做。
