你以為的門檻，跟真正的門檻不一樣

上週二晚上快九點，一個在社區藥局顧櫃檯的女生傳訊息給我，說她白天花了三個小時想搞懂 Codex，最後連「這東西到底在幫我做什麼」都講不出來。她問：「老師，我連 if、else 是什麼都不知道，學這個是不是在浪費時間？」

先把答案講在前面：不懂程式的人學 Codex，不會浪費時間，但你得先搞清楚一件事——你要學的不是寫程式，是把你每天重複在做的雜事，用人話講清楚，讓它幫你變成可以自動跑一次的流程。這兩件事差很遠。多數人一開始把力氣花在背語法，結果三小時後一無所獲，就是搞錯了方向。

你以為的門檻，跟真正的門檻不一樣

那個藥局女生，白天的三小時在幹嘛？她去 YouTube 找「Codex 教學」，影片一開頭就在講變數、函式、迴圈，她聽到第八分鐘就關掉了。她以為自己得先讀完一本程式書，才有資格開始。

其實剛好相反。Codex 這類工具最大的轉變，是你不再需要先學會那套語言，才能叫電腦替你做事。你只要會用中文把一件事講清楚。真正卡住新手的，從來不是程式難，是他不知道自己想要什麼、也講不清楚。

我請她先別碰教學影片。我問她：你在藥局每個月最煩、最重複、最想找人幫你做的那件小事是什麼？她想了一下說，每個月月底要把三十幾個廠商寄來的進貨單，一張一張抄進 Excel，抄到眼睛痠。

好。那就是你的第一堂 Codex 教學，不是變數也不是迴圈。

從一件你原本手動做的小事開始

我讓她把那三十幾個檔案丟進一個資料夾，然後對 Codex 講一句她原本會對工讀生講的話：「這個資料夾裡有一堆進貨單，檔名很亂，幫我照日期改成 YYYY-MM-DD 開頭，改之前先列給我看你要改哪些，不要直接動。」

就這樣。她沒寫任何一行程式。Codex 讀了資料夾，列出它打算怎麼改，她看過覺得對，才讓它動手。四十秒的事，她原本要手動花二十分鐘。

那一刻她愣住，跟我說：「原來我不用懂程式，我只要懂我自己在做什麼。」

這句話，其實就是重點。學 Codex 對一個不懂程式的人來說，門檻不在技術，在於你能不能把一件模糊的雜事，拆成一句清楚的指令。你講得越含糊，它做得越離譜；你講得越具體，它幫你省的時間越多。這跟你懂不懂 if else 沒關係。

為什麼我會叫她「先看再動」

你可能注意到我剛剛那句指令裡有一段：「改之前先列給我看，不要直接動。」

這不是隨口加的。對新手來說，這一句是保命的。因為你看不懂它背後跑了什麼，唯一能保護你的，就是讓它先把「打算做什麼」攤開給你看，你確認了再放行。這個習慣，比任何語法都重要。

我教易經這麼多年，蒙卦講的就是這件事。蒙是山下有水，一個人剛開始學東西，眼前一片霧。卦辭裡有一句「匪我求童蒙，童蒙求我」，意思是不是老師去追著初學者跑，是初學者自己帶著問題來問。學 Codex 也一樣——它不會主動幫你想清楚你要什麼，是你帶著一個具體的問題去問它，它才給得出有用的答案。

蒙卦還有一句我很喜歡，「初筮告，再三瀆，瀆則不告」。第一次誠心問，它告訴你；你亂問、反覆問一樣含糊的東西，就得不到清楚的回應。這放在用 Codex 上，準得可怕。你把問題想清楚再開口，它一次就給你要的；你自己都搞不清楚想幹嘛，問十次也是白問。

所以我從來不覺得不懂程式是學 Codex 的障礙。真正的障礙是你懶得把問題想清楚。

那到底什麼人學了會浪費時間？

老實講，還是有的。如果你想的是「我學會 Codex 之後要去接案寫軟體賣錢」，那你確實得回頭補程式基礎，這條路騙不了人。Codex 幫你把想法變成能跑的東西，但你要對那個東西的品質負責、要能看懂它哪裡出錯，這就需要真功夫。

可是如果你跟那個藥局女生一樣，只是想讓每個月那些重複的雜事少花點時間、想讓自己一個人也能做完以前要兩個人做的事——那你不用等到懂程式的那天。你今天就可以開始，從你手邊最煩的那件小事開始。

她後來又問我一句：「那我要多久才學得會？」

我說，你已經學會了。你剛剛不就做完一件了嗎。剩下的，就是下次遇到別的雜事，你記得回來問它一次。

常見問題

我真的一行程式都不會，用 Codex 會不會很危險，把電腦搞壞？
不會，只要你養成一個習慣：叫它做任何會動到檔案的事之前，先加一句「先列給我看要改什麼，不要直接動」。它會把打算做的事攤開給你確認，你看過再放行。危險的不是工具，是你在還沒看清楚前就讓它亂跑。
學 Codex 跟直接找工讀生幫我做，差在哪？
工讀生下班就走了，這個月教會的事，下個月換人又要重教。Codex 是你把一件事講清楚一次，之後每個月都能重跑。差別不在誰做得快，在於這件事會不會累積在你手上。
我年紀不小了，還學得會嗎？
會。因為你要學的是把你原本就熟的工作講清楚，不是背新的語法。你在自己行業做了十幾二十年，本來就比任何人都清楚「哪件事該怎麼做」，這正是用 Codex 最需要的東西。年輕人反而常常打字快、卻講不清楚自己要什麼。
