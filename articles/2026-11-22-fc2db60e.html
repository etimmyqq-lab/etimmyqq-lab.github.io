老闆真正要懂的三件事

十一月六號下午，雲林斗六一家做寵物飼料代工的公司，二樓辦公室。老闆五十三歲，筆電架在桌上，螢幕裡是他兒子幫他裝好的 Claude Code。他跟我說：我學了十一天，到現在只記得四句話，而且其中三句還不是指令，是我用中文打給它的要求。

我說那就夠了，夠你管事。

他不信。他以為要管這件事，至少得看懂程式碼在寫什麼。

這個問題我被問過不只一次。五十歲上下的老闆，公司三十到八十人，二代或者某個年輕員工拿 Claude Code 做了點東西出來，老闆要決定能不能用。他真正的焦慮其實不是「我會不會寫程式」，是「我會不會被騙」。怕有人端一個他看不懂的東西來說這個能省三小時，他點頭了，三個月後出事，他連為什麼出事都問不出口。

所以 Claude Code 教學對老闆來講，重點從來不在語法。

老闆真正要懂的三件事

第一，它要動哪些檔案。

第二，它動之前有沒有先跟你說。

第三，出事能不能退回去。

就這三件。沒有第四件。

第一件比想像中好學。Claude Code 改東西的時候會把檔案名稱列出來，紅色是刪掉的行，綠色是加上去的行。你不用看懂那些行在寫什麼，你只要看檔案名稱有沒有超出你交代的範圍。你叫它改報價單，它卻動到客戶資料的檔案，這就是要喊停的時候。這個判斷不需要技術背景，需要的是你對自己公司業務的熟悉度，而那個東西你比任何工程師都強。

第二件是紀律問題，等一下講。

第三件最便宜，也最常被跳過。

師出以律，否臧凶

易經師卦的第一爻寫「師出以律，否臧凶」。帶兵出門要有紀律，沒紀律的話，打贏打輸都是凶。我第一次讀到覺得不對勁，打贏了為什麼還凶？

看企業拿 AI 改自己系統看多了，我才懂這句在講什麼。

斗六那位老闆第一次出事，是叫 Claude Code 幫報價單模板加一個運費欄位。加成功了，他很得意，拍照傳給我看。四十分鐘後業務跑來說，客戶編號那一欄不見了。它整理檔案的時候，順手把它判斷成沒在用的欄位清掉，一共十一個。

關鍵在這裡：運費那件事它做對了。做對了，但他不知道它還做了什麼。

這就是否臧凶。贏得不明不白，等於沒贏，因為下一次你還是不知道該盯哪裡。

紀律長什麼樣子？在他這個案子裡，就一句話。他現在每次開口都先打這段：

「在你改任何檔案之前，先列出你打算改哪幾個檔案、每個檔案改什麼、為什麼要改。我說可以你才動手。」

貼上去，按 enter，然後等。它會回一張清單。你看清單，不看程式碼。這一步大概多花兩分鐘，省下來的是那四十分鐘加上一個下午的補救。

他現在會的四句話

一，這個專案在做什麼？用三句話講，不要給我程式碼。

二，改之前先列計畫，我同意你才動。

三，你剛剛改了哪些檔案？一個一個列出來。

四，`git commit -am "ok"`。

第四個是唯一一條真的指令，開工前在終端機敲一次，意思是把現在這個還能用的狀態存起來。出事就打 `git checkout .`，回到剛剛那個狀態。他把這兩行用麥克筆寫在便利貼上，貼在螢幕右下角的邊框。他說那是他的煞車。

他兒子覺得這樣太慢，每件事都要先列計畫再做，一個下午只做得完一件。

對，是比較慢。

不過老闆的工作本來就不是跑得快。老闆的工作是知道哪裡會垮，以及垮下來的時候手要往哪邊伸。這件事跟五十三歲還是二十七歲沒有關係，跟你有沒有被壞掉的東西燙過有關係。

至於真正要學的技術深度，我的看法是：你不需要知道它寫了什麼，你需要知道它碰了哪裡。前者是工程師的事，後者是你的事，而且只有你做得來。

那天我走之前，他指著那張便利貼問我：這樣我算懂 Claude Code 了嗎？

我說你不算懂，你算管得動。這兩件事本來就不一樣。廠裡那台沖床你也不會自己開，可是你知道哪個鈕是停。

常見問題

我完全不會寫程式，這樣學 Claude Code 會不會太勉強？
不會，因為你學的不是生產，是驗收。你要能看懂的只有兩樣東西：它列出來的檔案清單，以及它說它要做的事。這兩樣都是中文。真正會卡住你的不是技術，是你願不願意在它跑之前多等那兩分鐘。
員工用 Claude Code 做出來的東西，我怎麼判斷能不能上線？
問三個問題。改了哪些檔案？改之前有沒有存檔備份？壞掉怎麼退回去？前兩個答不出來還有救，第三個答不出來就先別上。我遇過的事故裡，九成都是因為沒有退路，不是因為程式寫得爛。
那大概要花多久才夠用？
斗六那位老闆是十一天，每天晚上四十分鐘左右，都在自己的筆電上試。他沒上過課。我的建議是不要先去學語法，先拿公司一個壞掉也不痛的小東西練手，例如某張不重要的報表。練到你敢在它動手前喊停，就夠了。
