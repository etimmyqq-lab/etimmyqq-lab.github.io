第一關：裝不起來

上個月台中一家四人會計師事務所的所長傳了一個截圖給我。螢幕上是一條英文報錯，紅底白字。他問：「老師，我是不是裝錯了？」

我看了三十秒。那條報錯的意思是「你的 Node.js 版本太舊，需要升級到 18 以上」。它本身不是錯誤，只是一個提示。但對一個從來沒開過終端機的人來說，紅字就等於壞事。

這是我近半年陪過的第三個「沒有 IT 人員自己裝 Claude Code」的案例。每次卡的地方不完全一樣，但有六個節點，幾乎每個案子都過不去。

第一關：裝不起來

不是 Claude Code 本身多難，是它需要一些前置條件：Node.js 版本、npm，還有讓系統找得到路徑的環境變數設定。

這些對 IT 人員來說是五分鐘的事。對一個平常只用 Excel 跟 Line 的人來說，光是「找到 Windows 的環境變數設定在哪裡」就需要二十分鐘。

更難的是：裝完之後看到一個黑色的視窗，裡面有一個游標在閃。很多人第一反應是「我是不是弄壞了什麼東西」。

我陪那個所長弄了三個下午，才讓他順利開啟 Claude Code 並跑出第一個回應。三個下午，不是三個小時。

第二關：API Key 沒人管

申請 Anthropic 帳號、拿到 API Key，這步驟本身不難。問題是：這把 Key 要用公司信箱還是私人信箱？費用誰支付、誰看帳單？

還有一個更現實的問題：如果 Key 是設在某個員工的電腦上，那個員工離職怎麼辦？

沒有 IT 人員的公司，通常也沒有人提前想這些。結果是老闆用個人信箱申請、私人信用卡付費，三個月後收到帳單才發現超支。

我遇過一個做五金代工的老闆，給四個業務員各自裝了 Claude Code、各自申請帳號，一個月下來帳單加起來台幣一萬八。他問我：「老師，這工具不是費用很低嗎？」

是低。前提是有人統一管。

第三關：不知道給 Claude 什麼權限

Claude Code 運作時需要存取你的檔案。它會詢問授權範圍。

這個問題對有資安概念的人來說很直覺，但對沒有相關背景的老闆來說非常困惑：我應該允許它讀哪些資料夾？它讀到財務報表之後，那些資料會跑去哪？

這些疑慮本身是合理的，問題是沒有人能給一個清楚的答案，結果就是：要麼全部允許（什麼都沒設限），要麼全部拒絕（每步都被卡住），工具用起來始終不順。

這讓我想到易經坎卦的一個核心：水往低處流，你得先知道低處在哪裡，才能決定怎麼走過去。導入 Claude Code 的時候，權限設定就是那個你要先看清楚的地形。不知道地形，走到一半才發現自己站在水裡。

第四關：報錯訊息全英文，沒人看得懂

Claude Code 的介面大部分是英文。錯誤訊息也是。

這在台灣的中小企業環境裡是真實的障礙。不是說英文不好就不能用，是說每次卡關都要另外找人翻譯解讀，這個額外成本是實際存在的。

那個所長傳來的截圖，我一眼看懂。但如果他在陪跑期之外遇到同樣的問題，他要怎麼辦？每次卡關都需要外部支援的工具，很難真正進入日常工作流程。工具會慢慢被放著不用，不是因為它不好，是因為每次卡住的成本太高。

第五關：裝好了不知道怎麼用

這個卡點比前面幾個更隱性，但可能是最致命的。

Claude Code 裝完，終端機打開，也能跑指令了。然後呢？

它不會主動問你今天有什麼事要幫忙。你需要主動用它，知道怎麼寫 prompt，知道把哪個工作交給它更有效率。

沒有 IT 人員的公司，通常也沒有人來設計這個工作流程。結果就是：工具裝了，偶爾試一兩次，然後慢慢沒人碰。三個月後再問老闆，他說「這工具沒什麼用」，但其實根本沒有認真用過。

這不是 Claude Code 的問題，是導入流程沒人設計的問題。

第六關：沒有人維護

Claude Code 會更新版本。有時候更新後某些指令的行為會改變，或者需要重新設定某些參數。

有 IT 人員的公司，這些事有人處理。沒有 IT 人員的公司，就是等到東西跑不動才知道。更常見的情況是：用了幾個月，某一天突然打不開了，沒人知道怎麼修，就這樣放著。

我最後幫那個台中所長做的事，是替他寫了一份「卡關應對 SOP」：六個最容易出問題的節點，每個節點該先確認什麼、出問題找誰。

他看完說：「這份 SOP 比 Claude Code 本身還有用。」

老實講，這句話讓我想了一陣子。工具能不能被真正用起來，跟工具本身的能力，其實是兩件完全不同的事。

對一個沒有 IT 人員的公司來說，在裝 Claude Code 之前，比較值得先回答的問題是：這六個卡點，你現在有幾個有答案？

有四個以上，可以開始動。

四個以下，先把那些答案找齊。

坎卦說的不是「不要過河」，是「先看清楚水流再走」。

常見問題

沒有 IT 人員，Claude Code 一定要找外部顧問陪才能裝嗎？
不是一定要。我見過有老闆靠著 YouTube 教學自己摸透的，花了大概兩週。重點不是要不要找人，是你要預留多少時間給「弄清楚」這件事。如果你打算自己來，三倍時間是基本預算。如果你的時間比錢貴，找人陪跑的效益會比較划算。
Claude Code 跟 ChatGPT 相比，沒有 IT 的公司哪個比較好導入？
這兩個工具的定位不太一樣。ChatGPT 是對話介面，打開網頁就能用，入門門檻低很多。Claude Code 是開發環境，需要終端機、環境設定、檔案存取授權。如果你的公司沒有任何人用過 terminal，Claude.ai 的對話版本會比 Claude Code 更適合作為第一步。兩個工具各有所用，先從門檻低的開始不是妥協，是務實。
如果我公司只有一個人願意學，這個人需要什麼技術底子？
不需要會寫程式，但需要不怕看英文、願意照著步驟試。Claude Code 的安裝和日常使用，有耐心的人大概可以在一週內摸熟基本操作。最關鍵的能力不是技術背景，是「出問題時知道去哪裡找答案」——Google、官方文件、問 AI。會用這三個管道，就夠了。
