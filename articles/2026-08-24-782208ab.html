這三件事，對機器來說是三種工作

上週五下午，一個做進口食品批發的老闆傳訊息給我，說他前一晚花了幾個小時想讓 Claude Code 一次幫他做三件事：把過夜沒看的 email 分類、把該回的訊息先擬好草稿、再把當天訂單彙成一張報表。弄到快兩點，三件事全做一半。email 分類是對的，回訊息回錯了對象，報表根本沒生出來。他問我一句：老師，是不是我太笨。

我說不是你笨，是你一次要它做三件事。

這篇就講一個很多人卡住的 Claude Code 教學問題：怎麼讓它同時整理信箱、回訊息、做報表。我的答案可能跟你想的相反。不是教你怎麼「一次設定好三件事」，是教你怎麼「一件一件接上去」。

這三件事，對機器來說是三種工作

整理 email、回訊息、做報表，你腦子裡把它們歸成「處理雜事」，很自然。但 Claude Code 讀到的是三種完全不同的任務。整理信箱是讀取跟分類，回訊息是生成內容還要判斷語氣跟對象，做報表是抓數字再算。這三件事需要的權限、要接的資料、出錯的後果都不一樣。

你把它們塞進同一句「幫我整理信箱回訊息做報表」，它會顧此失彼。那位老闆的回訊息回錯對象，就是因為它在同一輪裡又要分類又要生成，混了。

我常跟學員提易經的損卦。損卦講的不是損失，是減法：損之又損，把不必要的先拿掉，剩下的才做得好。設定 Claude Code 這種自動化，最容易犯的就是想一步到位。真正做得穩的人，反而是先砍到只剩一件事，跑順了，再加下一件。

實際的設定順序

我帶那位老闆重做，是這樣分的。

第一步，開一個資料夾當工作區，裡面放一個 `CLAUDE.md`。這個檔案就是你給它的常駐規則，你在裡面用中文寫清楚：這個信箱是誰的、哪些寄件人算重要、報表要哪幾欄。它每次啟動都會先讀這個檔。

第二步，只接 email 這一件。用 MCP 把 Gmail 連上來（`claude mcp add` 那條指令，現在有現成的 Gmail MCP 可以接）。接好之後，你只叫它做一件事：把昨天到現在的信分成「要回」「參考」「垃圾」三堆，列給你看。不要它動手回，先讓它列。你看它分得準不準，兩三天下來覺得穩了，才往下走。

第三步，加回訊息。這裡我建議做成一個 slash command，比方 `/擬回覆`，在指令裡寫死規則：只擬草稿、不准直接寄出、每一封都要標明回給誰。草稿擬好丟到一個資料夾，你早上花五分鐘看過再送。回訊息這件事永遠留一道人的關卡，這不是保守，是因為回錯一封信的代價，比省那五分鐘高太多。

第四步，才是報表。等前兩件都順了，你再讓它每天固定時間把訂單資料抓出來算成報表。這步反而最單純，因為報表是對數字，數字對不對你一眼看得出來。

為什麼順序不能顛倒

因為出錯的代價是遞增的。email 分錯，你重看一遍就好。訊息回錯，可能得罪客戶。報表算錯拿去做決策，那是真的會賠錢。從代價最低的先接，你有犯錯的空間，也才敢放手讓它多做。

那位老闆後來花了大概十天，一件一件接完。他跟我說，其實最後跑起來跟他原本想的一樣，就是同時做三件事。差別只在，他這次是分四次接上去的，中間每一步都確認過。

一步到位跟一件一件接，終點看起來一樣，路上的踏實程度差很多。損卦講的就是這個：你以為在減，其實是在讓它站得更穩。

常見問題

我不會寫程式，Claude Code 這種東西我裝得起來嗎？
裝得起來。Claude Code 是用講的，你在對話框打中文叫它做事就行，不用寫程式。真正要花時間的不是技術，是把你自己的規則講清楚：哪些信重要、報表要哪幾欄。這些只有你知道，它不會通靈。
一定要用 MCP 連 Gmail 嗎，感覺很複雜？
不一定，但要它讀你的信就得有個連法，MCP 是現在比較順的一種。如果覺得複雜，第一次可以找人幫你接一次，接好之後你日常用完全不碰那層。設定是一次的事，用是每天的事。
我可以真的讓它自動把信回出去嗎？
技術上可以，但我不建議，至少一開始不要。回訊息牽涉語氣跟對象，機器判斷錯一次的代價太高。讓它擬草稿、你按送出，多花不到五分鐘，換掉一整類會得罪人的風險，划算。
