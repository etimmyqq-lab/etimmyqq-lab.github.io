工廠裡真正該自動化的，是「搬資料」不是「做決策」

先講一個具體的：上週四下午，一家做汽車橡膠密封件的工廠，廠長在他辦公室那台舊電腦前坐了兩個多小時，就為了把六台射出機當天匯出的生產紀錄，一台一台複製貼進一張 Excel，再手算每台的良率。他做這件事做了九年，每天兩趟，早班一次晚班一次。我讓他打開 Claude Code，花了差不多四十分鐘，這件事以後變成兩秒。

所以「Claude Code 能幫工廠做什麼自動化」這個問題，我的答案很直接：它最擅長的不是取代機台、不是接手產線，而是接手你和你幹部每天用手在做、電腦其實可以做的那些搬運資料的動作。工廠裡這種動作多到你自己都沒察覺。

工廠裡真正該自動化的，是「搬資料」不是「做決策」

我陪傳產跑了這幾年，發現一個很一致的現象：老闆們一聽到自動化，想的都是很大的東西，機械手臂、無人倉、AGV。這些當然存在，但那是幾百萬起跳、要停線施工的事。而每天真正在偷走你幹部時間的，是這些沒人正眼看的小動作。

那家橡膠廠的廠長，他一天的行政時間我算給他聽：早上彙整六台機台紀錄大概五十分鐘，中午把品檢拍的照片依模具編號改檔名歸檔二十分鐘，下午把三個供應商的到料明細對進料單三十分鐘，晚班再彙整一次五十分鐘。加起來快兩個半小時，一週五天就是十二個多小時。他一個月薪水攤下來，等於有一個多禮拜的工時是在做電腦能做的搬運。

Claude Code 能吃下的，正好就是這一塊。它是一個你用中文交代、它幫你把小程式寫出來並跑起來的工具。你不需要會寫程式。你要會的，是把「我每天在幹嘛」講清楚。

三件我實際幫工廠做過的事

第一件，機台紀錄自動彙整。橡膠廠那六台射出機，每台會匯出一個 csv 檔到同一個資料夾。我讓廠長在那台電腦開 Claude Code，`cd` 進那個資料夾，然後就用講的：「這個資料夾每天會多六個機台匯出的 csv，欄位有生產數、不良數、模號，幫我寫一支程式，把它們合併成一張日報，每台算出良率，不良率超過百分之三的那一列標紅色。」它寫完、跑給你看、你說哪裡不對它就改。四十分鐘後，廠長以後只要雙擊一個檔案，日報自己生出來。

第二件，品檢照片歸檔。做精密的廠幾乎都有這個痛：品檢人員一天拍幾百張照片，檔名是相機給的 IMG_4471 這種，事後要對編號翻到死。我讓 Claude Code 寫了個小工具，監看那個照片資料夾，只要有新照片進來，就依照當下的工單號和模具號自動改檔名分類。品檢不用動，繼續拍就好。

第三件，到料對單。這件最多工廠在做，也最容易錯。供應商寄 Excel 報價或到料明細，格式每家都不一樣，人工比對進料單很花眼力。Claude Code 可以幫你把三家不同格式的表，讀進來、對到你的採購單、把數量對不上或單價跳動的挑出來。

這三件的共通點，你有沒有看出來：都是規則清楚、重複、而且錯了很煩但不難判斷對錯的事。這種事交給它，最安全。

用易經的角度看，這其實是「損」

我平常也拿易經卦牌幫老闆問方向，所以請容我用一個東方的角度講這件事。易經有個損卦，很多人一看到「損」字就覺得是壞的，其實它講的是有意識地減去。減去多餘的、佔用你精力的，好讓真正重要的東西浮出來。

工廠導入 Claude Code 做自動化，本質上就是在做損卦這件事。你不是要它變強、變大、變聰明，你是要它幫你把每天那兩個半小時的搬運動作減掉，讓廠長的腦子空出來，去看那些機器看不到的東西：這批料的味道不太對、這個老師傅今天狀況不好、這個客戶的口氣變了。

易經還有一句我很喜歡，「幾者，動之微」，講的是徵兆都藏在很細微的地方。一個好廠長的價值，就在他能看見那個「幾」。但如果他一天有兩個半小時埋在複製貼上裡，他哪有餘力去看那個微弱的徵兆。所以自動化的真正目的，從來不是機器多做了什麼，而是人被還回來了多少判斷力。

這也是為什麼我一直跟老闆講，別問「Claude Code 能不能取代人」，要問「Claude Code 能不能把人從搬運裡撈出來」。前者是恐懼，後者才是策略。

要注意的邊界：哪些不要交給它

講了這麼多好處，也得說清楚坑。凡是牽涉到「判斷對錯要靠經驗、錯了代價很大」的事，別急著自動化。良率算出來它可以，但這批要不要出貨，人決定。料號對不上它可以挑出來，但要不要退貨、要不要跟供應商翻臉，人決定。

易經艮卦講「知止」，知道什麼地方該停下來。自動化最忌諱的就是一路推到底，把該由人扛的判斷也丟給程式。機器做搬運，人做取捨，這條線劃清楚，你導入 AI 才不會導出一堆沒人負責的決策。

那家橡膠廠的廠長，臨走前跟我說了一句我記到現在。他說，老師，我以前覺得我每天很忙很充實，現在才知道那個充實，有一半是假的。

就這樣。沒別的。

常見問題

我們工廠的電腦很舊，也沒有網路，Claude Code 能用嗎？
它需要能連網，這點跑不掉，因為運算在雲端。但電腦舊沒關係，它不吃你本機效能，寫出來的小程式也都是很輕的東西，十年前的辦公電腦跑日報綽綽有餘。真正的門檻不是硬體，是你那台機台匯不匯得出資料檔，匯得出就好辦。
我完全不會寫程式，交代給它會不會反而被它唬？
會有一點這個風險，老實講。它寫的東西你看不懂，只能看跑出來對不對。我的建議是第一支程式一定要用你手上已經有正確答案的舊資料去對，比如拿上個月你手算過的日報，讓它跑一次同一批資料，數字對得起來你才敢用在新資料上。用已知答案驗證未知工具，這招在工廠特別重要。
值得為了省那兩個小時特地學嗎？我怕學了用不起來。
如果你只是想省兩小時，可能真的不太划算，學習成本擺在那。但你換個角度：省下來的不是兩小時，是廠長的判斷力。一個能專心看產線、看人、看料的廠長，跟一個埋在 Excel 裡的廠長，一年下來的差別遠不只兩小時。要不要學，看你把時間算在哪一格。
