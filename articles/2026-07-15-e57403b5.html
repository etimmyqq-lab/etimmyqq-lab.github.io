卡關不在技術，在你不會「開口」

上週五晚上快十一點，一個做網頁接案的年輕人打視訊給我。螢幕分享出來，是一整片全黑的終端機，游標在那邊一閃一閃。他說：「老師，我照 YouTube 把 Claude Code 裝好了，環境也通了，然後我就坐在這裡兩個小時，不知道要打什麼。」

那個閃的游標，我看了很有感覺。因為自學 Claude Code 卡住的地方，十個有八個不是卡在裝不起來，是裝好了之後，人愣在那裡。

卡關不在技術，在你不會「開口」

我把自學者常卡的地方分成三層。

第一層是環境，這層其實最好過。裝 Node、設 PATH、跟終端機當朋友，這些網路上教學一大堆，跟著做，卡住了把錯誤訊息整段貼給 AI 問，通常半小時內能通。這層我不太擔心，因為它有標準答案，你 Google 得到，AI 也答得出來。

第二層開始難了。你會打字，但你不知道要「交代」到什麼程度。自學的人最常犯的一個毛病，是把 Claude Code 當成許願池。他打一句「幫我做一個訂單管理系統」，然後等。等出來的東西不對，他就再打一句「不是這樣」，再等。這樣來回八次，他覺得這工具好笨。

問題不在工具笨。問題在他沒把自己腦袋裡的東西講出來。他知道那個系統要能改單、要能匯出 Excel、要跑在他公司那台舊電腦上，可他一個字都沒說。AI 不是不會做，是你根本沒告訴它你要什麼。

這裡我常跟學生講易經的蒙卦。蒙卦的卦辭有一句：「匪我求童蒙，童蒙求我。初筮告，再三瀆，瀆則不告。」白話講就是，不是老師去求學生，是學生帶著真問題來求老師；你第一次認真問，我認真答，你同一個模糊問題翻來覆去問三次，那就是在耗，我也答不出東西。

Claude Code 就是這個道理。你第一次把需求講清楚，它給你的東西八成能用。你含糊地丟，含糊地嫌，來回瀆問，它只會愈跑愈歪。這不是玄學，這是你有沒有先把問題想清楚的差別。

只有帶過的人才知道的三個坑

第三層，是自學幾乎跳不過的，得有人在旁邊踹你一腳才會醒的坑。

第一個坑：不敢讓它做大，也不敢把它拆小。自學的人要嘛一次丟一個超大任務，結果它做到一半自己迷路；要嘛卡在一個小 bug 上跟它耗一整晚。老師會做的事，是教你把一件事切成「先讓它把資料表建好、跑起來、我看一眼、再往下」。一段一段來，每段結束你都看得懂它在幹嘛。這個節奏感，看教學影片學不會，得有人陪你切過幾次才有。

第二個坑：出錯時不會跟它「吵架」。程式出錯是正常的，重點是出錯之後怎麼辦。自學的人看到紅字就慌，直接把整段錯誤刪掉重來。有經驗的人會做的，是把錯誤訊息貼回去，加一句「這個錯是因為什麼，你先跟我解釋，先不要改」。讓它先講原因，你聽懂了，再讓它動手。這一步差很多，可你自己摸很難想到要這樣做。

第三個坑，也是最深的：你不知道什麼時候該停下來自己想。有些決策 AI 幫不了你。它可以幫你寫程式，但「這個功能到底該不該做」「這條路走下去三個月後會怎樣」，這種問題它給不了答案，因為答案在你這邊。自學的人容易養成一種依賴，什麼都丟給它，連方向都想讓它決定。

這就是為什麼我教企業主用 Claude Code，還會拉一張易經卦牌進來。工具幫你把事情做出來，卦牌逼你把方向想清楚。Claude 跑分析、寫程式，那是它的活；往哪走、值不值得走，那是你的活。兩個混在一起，就會卡。

老師的價值不是教指令

老實說，Claude Code 的指令、快捷鍵、設定，這些網路上都查得到，我教的東西沒有一樣是秘密。

那老師的價值在哪？在於當你卡在那個閃爍的游標前，有人能告訴你「你現在缺的不是一個指令，是你還沒想清楚你要什麼」。在於你跟它耗了一整晚 debug，有人能一眼看出「你這方向從第三步就錯了，退回去重切」。在於你想把所有決策都丟給 AI 時，有人擋你一下：「這個它不能幫你決定，這是你的事。」

那個打視訊給我的年輕人，後來我沒教他任何新指令。我只問他：「你到底想做一個給誰用、解決什麼問題的東西？」他愣了三秒，開始講。講完，那個全黑的終端機，他自己知道第一句要打什麼了。

常見問題

自學 Claude Code 到底要多久才會用？
看你卡在哪一層。純環境設定，認真弄一兩天就通。但「知道怎麼把需求講清楚、怎麼拆任務、出錯怎麼處理」這種，自己摸大概要一兩個月，而且很多人摸到一半就放棄了。有人帶著切過幾次，通常兩三週就抓到節奏。差別不在聰不聰明，在有沒有人幫你跳過那些鬼打牆的迴圈。
完全不會寫程式，能自學 Claude Code 嗎？
能，但你要接受一件事：你不會寫，不代表你不用懂邏輯。你還是得能把「我要什麼、分幾步、每步該長什麼樣」講清楚。這部分跟寫不寫程式沒關係，跟你會不會把問題想明白有關係。很多不會寫程式但很會交代事情的老闆，反而學得比工程師快。
網路免費教學那麼多，為什麼還要花錢找老師？
免費教學教你「怎麼裝、怎麼打指令」，這些確實不用花錢。花錢買的是另一件事：當你卡在自己看不見的盲點時，有人一眼指出來。你不會知道自己是因為需求沒講清楚才一直失敗，因為你以為你講清楚了。這種盲點，只有旁邊有個看過幾百個案例的人才點得破。
